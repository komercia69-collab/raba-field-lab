# Residual Problem Test — Reuse Before Build

**Status:** public working research method / non-canonical  
**Context:** RABA Field Lab  
**Authority effect:** none

## Purpose

The Residual Problem Test is a working research method for examining whether a meaningful governance problem remains after an external approach has been interpreted as strongly and fairly as available evidence allows.

The method is designed to reduce a simple but important research error:

> **Not publicly found ≠ absent ≠ not already under development.**

A visible gap in a product, framework, standard, discipline, or public description is not sufficient evidence that the underlying problem is unsolved.

It is also not sufficient justification for RABA to build a new mechanism.

## Core question

Before treating an apparent gap as a RABA research opportunity, ask:

> **If this external approach worked as intended and implemented the strongest reasonable version of its stated purpose, what material governance problem would still remain?**

If the problem disappears under that interpretation, there may be no residual problem for RABA to address.

If a problem remains, the next question is not immediately:

> What should RABA build?

It is:

> **Does an existing system, discipline, standard, organizational practice, or technical control already address it adequately?**

## Research path

A candidate problem should move through the following sequence:

`observed gap`

→ `hidden / non-public possibility check`

→ `strongest reasonable interpretation`

→ `adjacent solution search`

→ `governance dependency mapping`

→ `residual problem test`

→ `necessity challenge`

→ `possible research candidate`

No earlier stage is sufficient by itself to justify new RABA development.

## 1. Strongest reasonable interpretation

An external approach should not be evaluated only through its weakest implementation, incomplete documentation, or current public surface.

The research question is not:

> Where can we make this approach fail?

The stronger question is:

> **What would remain unresolved even if this approach worked well within its intended scope?**

This does not assume capabilities for which there is no evidence.

It is a counterfactual research discipline intended to avoid manufacturing differentiation from incomplete information.

## 2. Governance dependency mapping

Many systems solve one part of a governance problem while depending on another part having already been resolved elsewhere.

The relevant question is therefore not only:

> What does this system do?

but also:

> **What does this system assume has already been decided, authorized, defined, or made reliable elsewhere?**

Possible dependencies may include assumptions that:

- policy is already legitimate and sufficiently specified;
- the correct owner is already known;
- authority has already been established;
- escalation routes are appropriate;
- materiality thresholds are valid;
- acceptable consequences have already been defined;
- approval represents sufficient authorization;
- technical recovery is equivalent to governance recovery.

These are research questions, not evidence of a RABA gap.

## 3. Residual Problem Test

For each approach under examination, ask:

1. What problem does the approach already solve?
2. What does it explicitly receive as input?
3. What does it assume has already been resolved elsewhere?
4. What authority or governance assumptions are embedded in it?
5. What happens when the approach works as intended?
6. What meaningful governance problem, if any, still remains?
7. Is that remaining problem already addressed by another existing discipline, system, standard, practice, or control?
8. If not, is there enough evidence to justify further research?

A residual problem is therefore not simply something absent from one framework.

It is something that remains materially unresolved after both the external approach and relevant adjacent solutions have been given a fair examination.

## 4. Reuse before build

Where an adequate existing solution is found, the preferred research disposition is:

`reuse / reference / interface / interoperability`

rather than:

`duplicate development`

RABA should not reproduce a mechanism merely because that mechanism was not found in one particular external system.

An interface with an existing solution may be more appropriate than creating a RABA-specific equivalent.

## 5. Valid outcomes

The method does not require a finding in RABA's favor.

Valid outcomes include:

- **RABA adds no material information**
- **the external approach is stronger**
- **an existing discipline already resolves the problem**
- **the hypothesis is falsified**
- **no material residual is found**
- **evidence is insufficient**
- **a material unresolved residual remains**

Only the last outcome may justify a further RABA research candidate.

Even then, it does not authorize implementation, establish uniqueness, validate RABA, or create RABA canon.

## 6. Comparative use in the Field Lab

The Residual Problem Test can be combined with bounded comparative work.

A simple pattern is:

`Frozen reality`

→ `Approach A — independent interpretation`

→ `Approach B — independent interpretation`

→ `Approach C — independent interpretation`

→ `RABA — independent interpretation`

→ `Delta Map`

The purpose is not to manufacture consensus or identify a winner.

The useful question is:

> **What becomes invisible, transformed, or assumed when the same reality passes through different governance models?**

Differences may reveal a residual problem.

They may also show that another approach already handles the problem adequately.

Both are legitimate results.

## Research boundary

This method:

- does not establish RABA uniqueness;
- does not claim an empty market or research niche;
- does not treat missing public information as evidence of missing capability;
- does not authorize development of new RABA mechanisms;
- is not a certification or validation methodology;
- does not replace evidence-based comparative research;
- does not transform external evidence into approval;
- does not create RABA canon.

Field Lab research may challenge RABA assumptions.

It does not itself modify the RABA core.

## Research principle

> **The purpose of comparative research is not to find something RABA can own. It is to discover whether any material governance problem remains unresolved after existing approaches are given their strongest reasonable interpretation.**
